# Verify — 이 프로젝트의 완료 기준

"잘 동작하게"는 기준이 아니다. 아래 표가 이 프로젝트의 완료 기준이고, 전부 통과해야 완료다. 명령과 기준값은 CLAUDE.md 명령어 절과 같아야 한다(second-brain 도입 때 채운다).

| # | 기준 | 명령 | 통과 조건 |
|---|---|---|---|
| 1 | 컴파일·테스트·빌드 | `./gradlew build` | exit 0, 실패 0 (계획 태스크 1 에서 프로젝트를 만들기 전까지는 "해당 없음: 서버 코드 없음") |
| 2 | 마이그레이션 | `./gradlew test` 의 통합 테스트가 빈 DB 에 Flyway 를 처음부터 적용 | 적용 오류 0 |
| 3 | 커버리지 | 해당 없음 | 해당 없음: MVP 는 계획의 태스크별 검증 테스트가 기준이다 |
| 4 | 화면 | 해당 없음 | 해당 없음: 화면이 없는 API 서버다 |

## 절차
1. 표의 명령을 순서대로 **끝까지** 돌린다. 하나가 실패해도 멈추지 않는다. 전체 그림이 필요하다.
2. 결과 표: 기준 · 통과/미달 · 핵심 출력 1~3줄(실패한 테스트 이름, 타입 에러 `파일:줄`). 출력을 요약하지 말고 그대로 인용한다.
3. 전부 통과 → "완료 기준 충족". 하나라도 미달 → "미달" + 가장 먼저 고칠 것 **하나**(상류부터: 타입 → 테스트 → 빌드 → 커버리지).
4. 통과가 끝이 아니다. **만든 쪽이 검사하지 않는다.** `reviewer` 에이전트(`.claude/agents/reviewer.md`)에 diff 와 이 표만 주고 깨끗한 컨텍스트에서 문제를 찾게 한다. 작성자의 요약은 넘기지 않는다. `/code-review` 가 있으면 그것도 돌린다.

## 금지
- 기준을 낮춰 통과시키지 않는다(테스트 skip·assert 완화·커버리지 임계 하향·타임아웃 연장). 기준 변경은 사용자 승인 + 이 파일 수정을 별도 커밋으로.
- "아마 통과할 것"을 쓰지 않는다. 돌린 출력만 적는다.
