# 028. 프로필은 브랜드 그림 8종 중 번호 하나로 계정에 두고, 가입 때 꼭 고른다

> 상태: 활성 · 결정일 2026-11-19(소유자) · 같은 계획의 026(약관 동의) · 027(푸시 수신 동의)과 함께 · 계획 docs/plans/2026-11-19-signup-terms-push-consent.md · 계약은 docs/architecture.md "API 계약"

## 맥락
- 소유자(2026-11-19): 프로필은 브랜드 그림 8종(앱 `assets/brand/avatar-1~8.svg`) 중 하나를 가입의 닉네임 단계에서 고른다. 마이에서 바꿀 수 있다.

## 결정
1. **계정 칸**(V21, 더하기만): `avatar smallint`(1~8 check, null = 이 결정 전에 가입한 계정, 있던 행은 채우지 않는다).
2. **가입**의 `avatar` 필수(정수 1~8). 없거나 범위 밖이면 400 `INVALID_AVATAR` 이고 가입권은 쓰지 않는다. 판정은 닉네임 다음, 출생 정보 앞이다(결정 026 의 4번). 새 계정에만 저장한다(결정 026 의 3번).
3. **`PATCH /account { avatar? }`** 로 바꾸고 `GET /account` 에 `avatar`(옛 계정은 null). 범위 밖이면 400 `INVALID_AVATAR` 이고 같이 보낸 칸도 바꾸지 않는다.
4. 그림은 앱에 있고 서버는 번호만 둔다. 프로필 바꾸기는 감사 기록에 남기지 않는다. 탈퇴하면 계정 행과 함께 지워진다.

## 근거
- 번호로 두면 그림을 바꿔도 서버와 DB 는 그대로다.
- 범위는 DB check 와 서버 검사가 함께 지킨다 — 앱이 틀린 번호를 보내도 저장되지 않는다.

## 대안
- 프로필 사진 올리기 — 소유자가 8종 중 고르기로 정했다.
- 그림 이름(글자)으로 두기 — 번호가 짧고 범위 검사가 쉽다.
- 가입 때 선택(기본 그림) — 소유자가 닉네임 단계에서 고르게 했다.

## 결과·재검토 조건
- 그림 수가 바뀌면 V21 의 check 와 서버 검사 · 앱을 함께 바꾸는 새 마이그레이션과 새 결정이 필요하다.
- 처리방침의 수집 항목에 프로필 번호를 넣을지는 소유자가 정한다.
