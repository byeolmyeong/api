# 038. 나 탭 "일" 의 일 방식 막대 셋은 서버가 차트로 계산한 정수(10~90)이고, 모델은 쓰지 않는다

> 상태: 활성 · 결정일 2026-11-20(소유자 질문 · 답 11번 "서버가 차트로 계산한다" · 구현 승인) · 원본: 앱 저장소 `docs/raw/2026-11-20-session-owner-qna-home-me-timing.md` 11번 · 시안: 보드 12-11(나의 일 방식 — 혼자서↔함께 · 계획대로↔그때그때 · 꼼꼼하게↔빠르게) · 공식 초안: docs/drafts/2026-11-20-work-style-formula.md(초안 · 소유자 검토 필요) · 결정 030(나 탭 풀이의 WORK 영역) · 계획 docs/plans/2026-11-20-home-me-timing.md

## 맥락
- 시안 일 칩(12-11)에 막대 셋이 있고, 점의 위치는 왼쪽에서 잰 값이다(시안 HTML 의 32% · 30% · 38% — 그림의 예시 값). 앱은 숫자를 계산하지 않는다(앱 골든 룰).
- 소유자: 원소 비율 · 별자리 성질(시작 · 고정 · 변화) · 일 관련 하우스의 별로 정한 공식으로 서버가 계산한다. 같은 차트면 늘 같은 값, "숫자는 서버 코드가 계산한다"(11번). 공식 초안을 만들어 보인다.

## 결정
1. **값** `workStyle` = `{ together, flexible, fast }`, 각각 정수 10~90. 0 쪽이 왼쪽 말(혼자서 · 계획대로 · 꼼꼼하게), 100 쪽이 오른쪽 말(함께 · 그때그때 · 빠르게)이다. 나 탭 풀이의 `WORK` 영역에만 있다(결정 030).
2. **계산**은 `chart` 의 순수 함수 하나(`WorkStyle.kt`)가 차트만 받아 한다: 점마다 무게(해 · 달 3, 수성 · 금성 · 화성 2, 목성 · 토성 1, 바깥 행성 0.5, 시각을 알면 상승점 2 · 중천 1)를 주고, 원소 몫(불 · 흙 · 공기 · 물) · 성질 몫(시작 · 고정 · 변화) · 하우스 몫(축마다 정한 하우스 묶음)을 섞어 축마다 −1~1 의 값 `r` 을 얻은 뒤 `round(clamp(50 + 50·r, 10, 90))`. 가중치 · 하우스 묶음 · 계산 예는 공식 초안이 원본이다(소유자가 고친 값을 코드로 옮긴다).
3. **시각 "모름"** 이면 하우스 항과 상승점 · 중천을 빼고, 남은 항의 가중치를 합이 1 이 되게 다시 나눈다. 시각을 알 때와 값이 달라질 수 있다(같은 차트에 대해 늘 같은 값이라는 약속은 "같은 입력" 기준).
4. **10~90 으로 자른다**: 끝(0 · 100)에 붙은 점은 "완전히 한쪽" 으로 읽혀 단정이 된다. 모든 사람에게 양쪽이 조금씩 있다는 말투(시안)와 맞춘다.
5. 모델은 이 값을 쓰지 않고, 일 영역의 글에 숫자 · 퍼센트가 있으면 버린다(결정 030 의 6). 저장은 나 탭 풀이 본문에 함께 넣는다(읽을 때 다시 계산하지 않는다 — 공식이 바뀌어도 받은 풀이는 그대로).

## 근거
- 같은 차트에 같은 값이어야 믿을 수 있고, 계산은 기준값 테스트로 혼자 검증돼야 한다(골든 룰 "차트 계산은 chart 의 순수 함수").
- 원소 · 성질 · 하우스는 서양 점성술에서 기질을 읽는 기본 재료이고, 축마다 전통적인 짝(불 · 공기 = 밖으로, 흙 · 물 = 안으로 / 변화궁 = 유연, 고정궁 = 지속 / 화성 · 수성 = 속도와 방식)을 따른다.

## 대안
- 모델이 막대 값을 쓰기 — 같은 차트에서 값이 흔들리고, 숫자를 모델에게 맡기지 않는다는 원칙과 부딪힌다.
- 앱이 차트로 계산하기 — 앱 골든 룰 위반이고 계산이 두 언어에 생긴다.

## 결과·재검토 조건
- 공식은 초안이다. 소유자가 가중치를 고치면 초안을 고치고 코드 · 기준값 테스트를 함께 바꾼다(결정을 새로 쓰지 않는다 — 값의 모양 · 범위가 같으면).
- 막대를 다른 칩(관계 등)에도 두게 되면 그 축의 공식을 새 결정으로 더한다.
