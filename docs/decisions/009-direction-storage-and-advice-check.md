# 009. 방향성 제시는 주제·대상으로 한 번만 저장하고, 조언형인지 서버가 글자로 확인한다

> 상태: 활성 · 결정일 2026-11-11 · 제품 규칙의 원본: 앱 저장소 `docs/release-1.0.0.md` "F10", 앱 결정 014 · 번호 007·008 은 같은 날 다른 작업 브랜치가 쓰고 있어 009 로 잡았다.
> 대체 표시(2026-11-12): 아래 "미래(`FUTURE`)는 차트 해시" 한 줄은 docs/decisions/011-direction-future-and-synastry.md 가 대체한다. 나머지는 그대로다.

## 맥락
- F10 방향성 제시는 주제가 셋이다: 미래(리포트 시기에 붙는다)·이성(요약 해석 아래)·궁합(궁합 결과 아래). 이번에 만드는 것은 이성 하나이고, 나머지 둘은 리포트 시기(태스크 8b)와 궁합(태스크 9)이 들어온 뒤에 더한다.
- 세 주제는 "무엇에 대한 글인가"가 다르다. 이성은 내 차트, 미래는 내 차트의 시기, 궁합은 궁합 한 건이다. 주제마다 표를 따로 두면 같은 모양(제목 + 해 볼 만한 것 3개)을 세 번 만든다.
- F10 은 "조언형으로만 쓴다. 무슨 일이 일어난다고 쓰지 않는다"를 요구한다. 요약 해석·리포트는 이 규칙을 지시문에만 맡겼다. 방향성 제시는 글 전체가 "앞으로"를 말하는 글이라 앞일을 단정하는 문장이 섞이기 가장 쉽고, 저장본을 그대로 돌려주므로 한 번 섞이면 계속 남는다.

## 결정
- 저장은 표 하나 `directions`(소유자, 주제 `topic`, 대상 `target`, 본문)에 두고 `(owner_id, topic, target)` 을 unique 로 한다. `target` 은 글자 열이고 뜻은 주제가 정한다: 이성(`LOVE`)은 차트 해시(`birth.ChartInput.hash`, 요약 해석·리포트와 같은 값). 나중에 궁합(`SYNASTRY`)은 궁합 id, 미래(`FUTURE`)는 차트 해시(시기 계산이 같은 차트에서 나온다)를 넣는다. 외래 키는 소유자에만 건다.
- 경로는 계약 표에 이미 있던 `POST /directions` 하나로 하고 본문 `{ topic }` 으로 주제를 받는다. 지금은 `LOVE` 만 받고 다른 값은 400 `INVALID_TOPIC` 이다.
- 요청은 요약 해석처럼 기다렸다가 답한다(저장본이 있으면 바로). 202 방식을 쓰지 않는다. 이유: 받는 글이 제목 한 줄과 항목 3개로 요약 해석(출력 약 1,900토큰, 23~40초)보다 짧다.
- 응답의 항목은 `{ title, body, basis[] }` 다. `title` 은 실천 한 줄이고 "~보기"로 끝난다(1.1.0 투두로 그대로 옮길 수 있는 모양). `basis` 는 요약 해석과 같은 말·같은 대조다.
- 서버가 저장 전에 조언형인지 글자로 본다(`direction/Direction.kt` 한 곳). 걸리면 근거가 틀린 글과 똑같이 버리고 다시 생성한다(처음 1번 + 다시 2번, 그래도 틀리면 502 `GENERATION_FAILED`, 저장하지 않는다).
  - 항목의 `title` 이 "보기"로 끝나지 않으면 버린다.
  - 제목·항목 제목·항목 본문 어디든 다음이 있으면 버린다: "반드시"·"틀림없이"·"운명", 앞일을 말하는 끝맺음(ㄹ 받침 글자 뒤의 "거예요"·"거에요"·"겁니다"·"것입니다"·"것이에요", 예: "만날 거예요"·"될 겁니다"), "~게 됩니다"·"~게 돼요".
- 건강·투자는 글자로 걸러 내지 않고 지시문에 맡긴다. 이유: "건강한 관계" 같은 보통 말이 걸린다.

## 대안
- 주제마다 표를 따로(`love_directions` 등) — 같은 모양을 세 번 만들고, 주제가 늘 때마다 마이그레이션이 는다.
- `readings` 에 `kind = DIRECTION_LOVE` 로 넣기 — 표를 늘리지 않지만 `readings` 는 차트 해시와 공유 식별자가 필수라 궁합에 붙는 글을 담을 수 없고, 기능 패키지 `direction` 이 `reading` 의 표를 쓰게 된다.
- 조언형 여부를 지시문에만 맡기기(요약 해석과 같게) — 구현은 줄지만 F10 의 핵심 규칙을 확인 없이 저장한다.
- 조언형 여부를 모델에게 한 번 더 물어 판정 — 호출이 두 배가 되고 판정도 틀릴 수 있다.

## 결과·재검토 조건
- 글자로 보는 규칙은 좁게 잡았다. 돌려 말한 단정("곧 좋은 사람이 나타나요")은 못 잡는다. 지시문이 1차이고 이 검사는 흔한 꼴만 막는 2차다.
- 반대로 "도움이 될 거예요" 같은 부드러운 말도 걸려 다시 생성한다. 실제 모델에서 이 때문에 502 가 잦으면 규칙을 줄이거나 지시문을 고친다. [확인 필요] 실제 모델로 돌려 본 적이 없다.
- 미래·궁합 주제를 더할 때 `target` 에 넣는 값이 여기 적은 것과 달라지면 이 문서를 새 번호로 대체한다.
