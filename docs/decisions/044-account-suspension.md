# 044. 이용 정지된 계정은 문의 · 로그아웃 · 계정 삭제 말고 모두 막는다

> 상태: 활성 · 결정일 2026-11-20(소유자 "열어놔야지" — 정지 계정도 문의하기는 연다) · 결정 043(관리자 API v2)의 정지 · 해제가 만드는 상태 · 앱 결정 065 의 5번(정지 화면 22) · 시안: 캔버스 "공통 상태" 22 · "어드민" D12 · D26 · D26-1

## 결정
1. **상태**: 계정에 `suspended_at timestamptz null` · `suspended_by`(관리자 id) · `suspension_reason text`(내부 기록, 앱에 보이지 않음). 해제하면 셋을 비우고 감사 기록에 해제 사유를 남긴다.
2. **막는 범위**: 정지된 계정의 사용자 세션으로 온 요청은 403 `ACCOUNT_SUSPENDED`. 다만 아래는 연다.
   - `POST /inquiries` · `GET /inquiries` · `GET /inquiries/{id}`(잘못된 정지를 바로잡을 연락 길 — 소유자 결정)
   - `GET /account`(앱이 정지 상태를 알고 22 를 그리게 응답에 `suspended: true`)
   - 로그아웃 · `DELETE /account`(스스로 떠날 수 있다)
   - 로그인 · 가입은 그대로 되고 세션을 준다(세션이 있어야 문의할 수 있다). 앱은 그 뒤 첫 요청의 403 이나 `GET /account` 로 22 를 띄운다.
3. **함께 멈추는 것**: 정지된 계정에는 푸시를 보내지 않는다(오늘의 하늘 · 풀이 완성 · 문의 답변 · 광고 모두). 오늘의 하늘 미리 만들기도 건너뛴다. 생성 중이던 일은 끝까지 하되 알림은 알림함에만 둔다.
4. **검사 자리**: 세션 검사 바로 뒤(점검 503 · 강제 업데이트 426 은 그보다 먼저). 정지 여부는 세션을 확인할 때 계정과 함께 읽는다(요청마다 쿼리를 더하지 않는다).
5. **문의 제한**: 정지 계정의 문의에도 지금의 계정별 시간당 제한(결정 013)이 그대로 걸린다.

## 근거
- 정지는 "앱을 쓰지 못하게" 가 목적이고, 연락 길까지 막으면 잘못된 정지를 풀 길이 없다.
- 스스로 탈퇴는 개인정보 보호법상 막을 수 없다.

## 대안
- 로그인 자체를 막기 — 그러면 문의를 보낼 세션이 없다.
- 문의를 이메일로만 받기 — 앱 안 답변(결정 039)과 길이 둘이 된다.

## 결과·재검토 조건
- 앱은 403 `ACCOUNT_SUSPENDED` 를 받으면 어디서든 22 로 간다(앱 결정 065, 계획 A⑦).
- 기간이 정해진 정지(며칠 뒤 자동 해제)가 필요해지면 `suspended_until` 을 더한다 — 지금은 관리자가 푼다.
