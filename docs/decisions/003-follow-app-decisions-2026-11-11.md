# 003. 앱 저장소의 2026-11-11 결정(009~015)을 서버 설계에 반영한다

> 상태: 활성 · 결정일 2026-11-11 · 앱 쪽 기록: 앱 저장소 `docs/decisions/009`~`015`, 명세 `docs/release-1.0.0.md` · docs/decisions/002-chart-calculation.md 의 "차트 계산은 로그인 없이 받는다"를 대체한다(002 의 나머지는 그대로)

## 맥락
2026-11-11 기획 정리에서 앱 저장소가 가입 시점·로그인 수단·연령 제한·궁합 점수·랭킹·변곡점 범위·횟수 제한·광고를 새로 정했다. 서버 설계(docs/architecture.md)와 계획(docs/plans/2026-11-10-api-mvp.md)은 그 전 결정 기준이다.

## 결정
- 로그인(앱 009): 구글·애플·카카오. 스플래시 직후 가입이 필수라 `POST /charts` 도 세션을 요구한다. 로그인 없이 받는 요청은 `GET /places`(가입 중 출생지 검색), `GET /invites/{id}`, `GET /shared/{shareId}` 뿐이다. 가입 때 만 14세 이상인지 확인하고, 만 14세 미만은 계정을 만들지 않는다.
- 궁합(앱 010): 나 기준 점수(40~100)를 서버 코드가 계산한다. 관계 유형(연애·친구·일)마다 따로 계산한다. 나 기준으로 여러 명과 1:1 매칭한 결과를 관계 유형별 랭킹으로 돌려준다. 인원 제한은 없다.
- 횟수 제한(앱 011): 리포트·궁합의 기능 횟수 제한을 없앤다. 주소·계정별 요청 속도 제한(남용 방지)만 둔다.
- 변곡점(앱 012): 정해진 마디에 더해 변화 구간(토성·외행성 × 태양·달·상승점, 합·사분·충), 기회 구간(목성 × 태양·달·상승점·중천·금성 합·삼분, 목성의 5·7·11하우스 통과), 운명적 만남 구간(목성·토성·외행성 × 버텍스 합, 시각을 알 때만)을 계산한다. 구간마다 기간·영역·크기를 붙인다.
- 차트(앱 012): 추가 지점에 버텍스를 넣는다(시각을 알 때만). 키론은 넣지 않는다.
- 방향성 제시(앱 014): 1.0.0 에 무료로 생성한다. 투두·조각·레벨업은 1.1.0 이다.
- 광고(앱 015): 1.1.0 부터다. 1.0.0 서버에는 광고 판정이 없다.

## 근거
- 계산(점수·구간·버텍스)과 판정(만 14세, 소유자)은 서버에서만 해야 조작할 수 없다(002, 앱 golden-rules 프로젝트 규칙).
- 앱 기획의 원본은 앱 저장소다. 서버는 그 결정을 계약과 구현 계획으로 옮긴다.

## 대안
- 로그인 없는 `POST /charts` 유지 — 가입 전에 출생 정보를 받는 흐름이 앱에서 없어졌다.

## 결과·재검토 조건
- docs/architecture.md 의 계약 표·데이터·횟수 제한 절과 계획의 태스크 6·8·9·10 을 고친다. 방향성 제시는 태스크 12 로 더한다.
- 이미 구현된 로그인 없는 `POST /charts`(태스크 5)는 태스크 6(로그인)이 끝난 뒤 세션을 요구하도록 바꾼다. 그 전까지는 지금처럼 둔다.
- [확인 필요] 만 14세 확인 방법(가입 화면의 생년월일 / 카카오 연령대 동의 항목), 궁합 점수 합산값 → 40~100 변환 구간.
