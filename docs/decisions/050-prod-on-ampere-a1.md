# 050. 운영 서버는 Ampere A1(2 OCPU · 12GB, arm64)에 두고, 계정은 종량제로 올린다

> 상태: 활성 · 결정일 2026-11-20(소유자 "서버를 오라클 Always Free Ampere A1 으로 옮긴다" · "운영만" · "종량제 전환 OK, 전환 때 점검 화면 3~5분 OK") · 계획 docs/plans/2026-11-20-prod-to-a1.md · 결정 020 #1 의 운영 셰이프와 "compose 에 JVM 옵션을 두지 않는다"(046 이 이미 대체), 046 #7 의 힙 256m 고정을 운영에 한해 대체한다(스테이징은 그대로)

## 맥락
- 결정 046(블루 · 그린)으로 배포 때 JVM 둘이 잠깐 함께 뜬다. E2.1.Micro(1GB · 1/8 OCPU 기준의 버스트 CPU)인 스테이징에서 재 보니 그동안 VM 전체가 느려졌다: 새 JVM 시작 121~187초(187초는 `/health` 3분을 넘겨 바꾸지 않고 실패), load 9.7, 응답 최대 9~10초, 평소에도 CPU steal 2~10% · 스왑 사용(2026-11-20).
- 운영은 끊기거나 느려지면 안 된다(소유자). 운영도 같은 E2.1.Micro 다.
- 결정 020 은 "출시가 가까워질 때 운영 서버를 더 큰 서버로 옮긴다(종량제로 올려 A1 이 생기면 A1)" 를 재검토 조건으로 두었다. 2026-11-18 조회에서 이 계정(무료)의 A1 한도는 0 이었다.
- 2026년에 Always Free A1 한도가 4 OCPU · 24GB → 2 OCPU · 12GB 로 줄었다는 보도가 여럿 있다(시행일은 6/15 · 8/18 로 갈림, 공식 문서는 옛 숫자로 보이기도 함). 실제 값은 콘솔의 한도 화면이 원본이다(결정 020 "무료 한도").

## 결정
1. **운영 서버 = `VM.Standard.A1.Flex` 2 OCPU · 12GB**, Ubuntu 24.04 Minimal aarch64, 춘천, 같은 VCN · 공개 서브넷. 만들 때 "Always Free-eligible" 표시를 확인한다. 4 OCPU · 24GB 는 쓰지 않는다(보도된 새 한도를 넘을 수 있고 운영에는 2 · 12 로 충분하다).
2. **스테이징은 E2.1.Micro 그대로**다(소유자). 그래서 스테이징에서 잰 배포 끊김 · 느려짐은 운영보다 나쁘게 나온다 — 운영의 기대치로 읽지 않는다.
3. **계정을 종량제(Pay As You Go)로 올린다.** 까닭: 무료 계정은 A1 한도가 0 이거나 용량이 모자라는 일이 잦고, 무료 계정의 A1 은 7일 동안 CPU · 네트워크 · **메모리** 사용률이 20% 아래면 회수될 수 있다(12GB 에서 우리는 1~2GB 를 쓴다). 종량제 계정은 회수 대상이 아니고, Always Free 범위 안이면 0원이다. 올리면 예산 알림(월 1달러)을 건다.
   - 과금이 생길 수 있는 것은 쓰지 않는다: 유료 셰이프 · 무료를 넘는 블록 스토리지(부트 볼륨 합 200GB) · 로드 밸런서 · 무료를 넘는 예약 IP.
4. **JVM 힙은 VM 마다 `.env` 의 `API_HEAP_MAX`**(compose `-Xmx${API_HEAP_MAX:-256m}`): 운영 `1g`, 스테이징은 비워 256m. 1g × 2(겹칠 때) + 비힙 + Postgres · Caddy 는 12GB 의 1/4 아래다. `-XX:+ExitOnOutOfMemoryError` 는 그대로.
5. **새 VM 은 처음부터 블루 · 그린**(docs/deploy.md (다) "새 VM 에 처음 띄우기"). 옛 운영 VM 은 블루 · 그린으로 옮기지 않고 전환 뒤 지운다.
6. **옮기기 = 점검 모드(결정 017) 3~5분 안에 마지막 덤프 → 새 VM 복원 → DNS(Cloudflare A 레코드, TTL 60초) 바꾸기.** 아키텍처가 달라 DB 볼륨이 아니라 덤프로 옮긴다. 운영 덤프는 VCN 안에서 옛 운영 VM → 새 운영 VM 으로만 옮긴다(결정 020 #5 그대로).

## 근거
- 2 OCPU(Ampere 코어, SMT 없음) · 12GB 면 JVM 둘이 겹쳐도 스왑 없이 남는다. CPU 기준값을 버스트로 깎지 않는다.
- 종량제는 돈을 쓰자는 것이 아니라 회수 · 한도 · 용량 위험을 없애려는 것이다. 예산 알림으로 실수를 바로 안다.
- 힙을 `.env` 로 빼면 compose 파일 하나를 두 크기의 VM 이 같이 쓴다.

## 대안
- E2.1.Micro 에서 JVM 옵션만 조정(CDS · C1 만 · Serial GC): 시작 CPU 를 줄여도 1GB · 버스트 CPU 의 겹침은 남는다.
- 무료 계정 그대로 A1: 회수 · 한도 0 위험.
- 유료 VPS · 유료 셰이프: 돈이 든다. A1 을 못 만들 때 다시 본다(결정 020 재검토 조건).
- 스테이징도 A1: 소유자가 그대로 두기로 했다.

## 결과·재검토 조건
- 운영 · 스테이징의 크기가 달라진다. 배포 시간 · 응답 시간은 스테이징이 늘 더 나쁘다.
- 다시 본다: 콘솔의 A1 한도가 2 · 12 아래로 줄 때, 종량제 비용이 0 이 아닐 때(예산 알림), 오라클이 A1 정책을 바꿀 때, 출시 뒤 동시 생성이 늘어 2 OCPU 가 모자랄 때.
