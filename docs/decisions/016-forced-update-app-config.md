# 016. 앱의 최소 버전을 서버가 갖고, 급할 때는 낮은 버전의 요청을 426 으로 막는다

> 상태: 활성 · 결정일 2026-11-12(소유자) · 계약은 docs/architecture.md "API 계약" 의 "앱 설정과 강제 업데이트", "관리자 API" 의 "앱 설정"

## 맥락
- 출시 뒤에 계약이 바뀌거나 치명적인 오류가 있는 버전이 스토어에 남으면, 그 버전을 쓰는 사람에게 업데이트하라고 알릴 길이 없다.
- 앱이 시작할 때 설정을 읽어 안내 화면을 띄우는 것만으로는 이미 켜 둔 앱·설정 읽기를 건너뛰는 옛 버전을 막지 못한다.
- 관리 화면(결정 014)이 생겨 값을 고칠 곳이 있다.

## 결정
1. **테이블 `app_configs`(V14)**: 플랫폼(`ios`·`android`)마다 한 행. 최소 버전(`min_version`, 없을 수 있다)·스토어 주소·안내 글·`block_now`·고친 때·고친 관리자. 두 행은 마이그레이션이 넣는다(값은 모두 비어 있고 `block_now` 는 꺼져 있다). 행을 더하거나 지우는 길은 없다.
2. **공개 조회 `GET /app-config`**(세션 없음): 두 플랫폼의 `{ minVersion, storeUrl, message, blockNow }`. 앱이 시작할 때 읽어 자기 버전이 낮으면 안내한다(권하는 것인지 막는 것인지는 앱이 `blockNow` 로 가린다). 로그인 전 경로 목록에 GET 만 더하고, 주소별 분당 제한(`byeolmyeong.rate-limit.app-config-per-minute` 120)과 `Cache-Control: public, max-age=60` 을 붙인다.
3. **급할 때의 막기**: 앱은 모든 요청에 `X-App-Platform: ios|android`·`X-App-Version: <버전>` 을 보낸다(웹은 보내지 않는다). 그 플랫폼의 `block_now` 가 켜져 있고 `min_version` 이 있고 요청의 버전이 그보다 낮으면 **426 `{ "error": "UPDATE_REQUIRED" }`** 다.
   - 막지 않는 경로: `GET /app-config`(막힌 앱이 스토어 주소와 안내 글을 읽어야 한다) · `/health` · `/admin/**`(관리 화면은 어떤 경우에도 잠기지 않는다 — 잘못 넣은 값을 고칠 곳이다).
   - **모르면 막지 않는다**: 두 헤더가 없거나, 플랫폼이 `ios`·`android` 가 아니거나, 버전을 읽을 수 없으면 통과시킨다. 헤더는 누구나 지어낼 수 있으므로 이것은 보안 장치가 아니라 **정상적인 옛 앱에게 알리는 장치**다. 틀린 설정이 모든 사용자를 잠그는 쪽보다, 헤더를 지운 사람이 지나가는 쪽이 싸다.
   - 세션 검사보다 먼저 본다(인터셉터, 가장 앞 순서): 옛 앱은 401 이 아니라 426 을 받는다. 서블릿 필터가 아니라 인터셉터라 426 에도 CORS 허용 헤더가 붙고, 브라우저의 사전 요청(preflight)은 건드리지 않는다.
4. **버전 규칙**(`web.AppVersion`, 순수 함수): 점으로 나눈 1~3개의 0 이상 정수(`"1"`·`"1.2"`·`"1.2.3"`). 빠진 자리는 0 이다(`"1.2"` = `"1.2.0"`). 숫자로 견준다(`1.10.0` > `1.9.9`). 자리마다 9자리까지다. 그 밖(`"1.2.3.4"`·`"1.2-beta"`·`"v1.2"`·앞뒤 공백·빈 글)은 읽을 수 없는 값이다. 관리자가 넣는 `minVersion` 과 앱이 보내는 `X-App-Version` 에 같은 함수를 쓴다.
5. **관리자 API**: `GET /admin/app-config`(두 플랫폼 + 고친 때·고친 관리자) · `PUT /admin/app-config/{platform}`(네 값을 **모두** 보낸다 — 빠진 값이 실수로 지워지거나 남지 않게). `blockNow: true` 는 `minVersion` 이 있을 때만 된다(테이블의 check 도 같다). 스토어 주소는 `https://` 만 받는다(앱이 그 주소를 연다).
6. **값을 캐시한다**: 요청마다 DB 를 읽지 않게 두 행을 서버 메모리에 5초(`byeolmyeong.app-config.cache-seconds`) 둔다. 관리자가 고치면 `admin` 이 이벤트 `admin.AppConfigChanged` 를 내고 `appconfig` 가 캐시를 비운다(같은 서버에서는 바로 반영). 서버가 여러 대면 다른 서버는 길어야 5초 뒤에 따라온다.
7. **패키지**: 읽기·막기는 새 기능 패키지 `appconfig`, 쓰기는 `admin`(FAQ 와 같은 방식 — 두 패키지는 같은 테이블만 보고 코드로는 이벤트 하나로만 이어진다). 버전 규칙은 둘이 같이 쓰므로 `web` 에 둔다.
8. 고칠 때마다 감사 기록 `APP_CONFIG_UPDATED` 를 남긴다(결정 015): 플랫폼·최소 버전·`blockNow` 만. 안내 글과 스토어 주소는 남기지 않는다.

## 버린 대안
- 앱만 판단한다(`GET /app-config` 만) — 맥락의 둘째 줄.
- 헤더가 없으면 막는다(fail closed) — 웹과 `curl`·상태 확인이 모두 막히고, 헤더를 보내지 않는 옛 버전이 하나라도 있으면 설정 한 번에 전부 잠긴다.
- 서블릿 필터 — CORS 헤더가 붙지 않아 웹이 426 을 읽지 못한다(세션 검사와 같은 이유).
- `/admin/**` 도 같은 규칙 — 관리 화면이 잠기면 값을 되돌릴 길이 DB 뿐이다.
- 설정을 환경 변수에 — 바꾸려면 다시 배포해야 한다. 급할 때 쓰는 장치다.
- 캐시 없이 요청마다 읽기 — 모든 요청에 쿼리가 하나 는다. 캐시를 이벤트로만 비우기(시간 없음) — 서버가 여러 대면 다른 서버가 영영 옛 값을 본다.
- 플랫폼별 "권장 버전" 을 따로 — 요청에 없다. `blockNow: false` 인 `minVersion` 이 그 역할을 한다(앱이 안내만 한다).

## 영향
- 새 패키지 `appconfig`(ArchUnit 의 기능 목록), 이벤트 `admin.AppConfigChanged`(ArchUnit 의 이벤트 목록), `web.AppVersion`, `V14__app_configs.sql`. `auth` 의 로그인 전 GET 경로와 `web.RateLimitConfig` 가 경로 글자 `/app-config` 를 더 안다.
- 앱의 웹 빌드는 두 헤더를 보내지 않는다 — CORS 허용 헤더에 더하지 않았으므로 브라우저에서 보내면 사전 요청이 거절된다. 웹은 언제나 최신이라 막을 것이 없다.
- 426 은 없는 경로에도 온다(세션 검사와 같다). 앱은 어느 요청에서든 426 `UPDATE_REQUIRED` 를 받으면 `GET /app-config` 를 읽어 업데이트 화면을 띄운다.
- [확인 필요] 소유자: ① 스토어 주소를 `https://` 로만 받는다(`itms-apps://`·`market://` 는 거절). 앱이 그런 주소를 써야 하면 규칙을 넓힌다. ② `GET /app-config` 의 60초 캐시 때문에 CDN·프록시를 앞에 두면 `blockNow` 를 켜도 안내 화면의 글이 최대 60초 늦게 바뀐다(426 자체는 캐시와 상관없이 바로다).
