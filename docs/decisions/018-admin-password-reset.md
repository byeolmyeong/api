# 018. 관리자가 다른 관리자의 비밀번호를 다시 정해 줄 수 있다

> 상태: 활성 · 결정일 2026-11-12(소유자) · 결정 014 의 6번("비밀번호는 자기 것만 바꾼다")과 "[확인 필요] ① 비밀번호를 잊은 관리자를 다시 설정해 주는 기능이 없다" 를 **이 결정이 바꾼다**(014 의 나머지는 그대로다) · 계약은 docs/architecture.md "관리자 API" 의 "관리자 관리"
> 2026-11-20: 비밀번호를 정해 주는 방식은 결정 043 의 5번(서버가 만든 임시 비밀번호 재발급 · 첫 로그인에 바꾸기)으로 바뀌었다. 이 경로는 계획 S⑦ 정리 때 지운다.

## 맥락
- 결정 014 에서는 비밀번호를 잊은 관리자에게 새 계정을 만들어 줘야 했다. 처리 기록이 옛 계정에 남고 아이디를 다시 쓸 수 없다.

## 결정
1. `PUT /admin/admins/{id}/password` `{ password }` → 204. 역할 구분이 없으므로(결정 014) 관리자는 누구나 다른 관리자의 비밀번호를 다시 정할 수 있다. 비밀번호 규칙은 그대로다(10자 이상, 72바이트 이하).
2. **그 관리자의 세션을 모두 끝낸다** — 다시 정한다는 것은 예전 비밀번호를 믿지 않는다는 뜻이다.
3. **자기 자신에게는 쓸 수 없다**(409 `USE_OWN_PASSWORD_CHANGE`). 자기 비밀번호는 지금 비밀번호를 아는 것을 보여야 하는 `PUT /admin/me/password` 로만 바꾼다 — 아니면 열려 있는 세션 하나를 훔친 사람이 비밀번호를 바꿔 계정을 가져간다.
4. 꺼진 관리자에게도 된다. 켜지지는 않는다(켜는 것은 `PATCH /admin/admins/{id}`).
5. 감사 기록 `ADMIN_PASSWORD_RESET`(대상 = 그 관리자, 결정 015). 비밀번호는 로그·기록 어디에도 없다.

## 버린 대안
- 메일로 재설정 링크 — 메일 발송이 없다(결정 013·014).
- 임시 비밀번호를 서버가 만들어 응답으로 준다 — 응답에 비밀번호가 실린다. 정해 주는 관리자가 직접 넣고 따로 전한다.
- 다음 로그인 때 바꾸게 강제 — 요청에 없다. 받은 관리자가 `PUT /admin/me/password` 로 바꾼다(화면이 안내한다).

## 영향
- 관리자 한 명의 세션을 훔치면 다른 관리자 모두의 비밀번호를 바꿀 수 있다(이미 다른 관리자를 끄고 새 관리자를 만들 수 있었으므로 권한이 넓어진 것은 아니다). 감사 기록에 남는다.
- 관리자가 한 명뿐인데 잊으면 여전히 DB 에서 그 행을 지우고 환경 변수로 다시 만든다(결정 014).
