# 045. 약관 · 처리방침 버전을 바꿀 때 옛 버전을 잠깐 함께 받고, 계정 · 감사 기록에는 사람이 보낸 버전을 남긴다

> 상태: 활성 · 결정일 2026-11-20(소유자 "잠깐 둘 다 받기") · 결정 026 의 3번 "지금 버전과 둘 다 글자 그대로 같을 때만" 과 5번 감사 기록의 버전을 대체한다(026 의 나머지는 그대로다) · 랜딩 약관에서 궁합을 뺀 판(랜딩 main 4eaca8e, 시행일 2026-11-20) · 앱 결정 043(앱 약관 글 = 랜딩 글) · 계약은 docs/architecture.md "API 계약"

## 맥락
- 소유자 지시("없애야할 것 같은데 궁합관련은?")로 랜딩의 이용약관 · 개인정보 처리방침에서 궁합을 뺐다. 시행일과 버전이 2026-11-19 → 2026-11-20 이 된다.
- 결정 026 은 가입 때 앱이 보낸 버전이 서버의 지금 버전과 정확히 같을 때만 받는다. 서버만 2026-11-20 으로 바꾸면 이미 깔린 TestFlight 테스트앱(2026-11-19 를 보낸다)의 가입이 모두 400 `TERMS_REQUIRED` 가 된다. 앱을 먼저 바꾸면 반대로 새 앱의 가입이 막힌다.
- 지금 서버는 가입 감사 기록 `TERMS_AGREED` 의 detail 에 사람이 보낸 값이 아니라 서버 설정 값을 적는다. 정확히 같을 때만 받으니 지금까지는 같은 값이었지만, 옛 버전을 받기 시작하면 틀린 기록이 된다.

## 결정
1. **설정**: 지금 버전 `byeolmyeong.legal.terms-version` · `privacy-version`(2026-11-20) 옆에 함께 받는 옛 버전 목록 `byeolmyeong.legal.terms-previous-versions` · `privacy-previous-versions`(쉼표로 여럿, 앞뒤 공백은 뗀다, 비어도 된다 — 비면 지금 버전만 받는다)를 둔다. 지금은 둘 다 `2026-11-19`. 지금 버전이 비면 서버가 시작하지 않는 것은 결정 026 그대로다.
2. **가입**(`POST /auth/signup`): `termsVersion` 이 이용약관의 지금 버전이나 옛 목록 중 하나와, `privacyVersion` 이 처리방침의 지금 버전이나 옛 목록 중 하나와 각각 글자 그대로 같으면 받는다. 둘이 섞여도(한쪽만 옛 버전) 받는다. 없거나 목록 밖이면 400 `TERMS_REQUIRED` 이고 가입권은 남는다(결정 026 그대로). 판정 순서도 그대로다.
3. **기록**: 계정 행의 `terms_version` · `privacy_version` 과 감사 기록 `TERMS_AGREED` 의 detail `{ termsVersion, privacyVersion }` 에는 사람이 실제로 보낸(그래서 받은) 버전을 남긴다. 서버 설정 값을 적지 않는다.
4. **옛 버전 지우기**: 새 버전을 보내는 앱(이번에는 새 TestFlight 빌드)이 나오고 옛 앱의 가입을 막아도 되면 옛 목록을 비운다. 이 결정의 일이 아니라 따로 한 커밋으로 한다.

## 근거
- 서버가 먼저 두 버전을 다 받으면 서버 → 앱 순서로 하루 사이에 바꿔도 어느 쪽 앱의 가입도 깨지지 않는다.
- "누가 어느 판에 동의했나" 의 답은 사람이 본 판이어야 한다. 받은 값을 그대로 남기면 옛 판으로 가입한 사람도 옛 판으로 기록된다.
- 약관 · 처리방침을 따로 두면 하나만 고치는 날에도 같은 방식으로 쓴다.

## 대안
- 서버 · 앱을 같은 때 바꾸기(026 그대로) — 이미 깔린 테스트앱은 업데이트 전까지 가입이 막힌다.
- 날짜(예: 2026-11-19 이후의 아무 판)로 받기 — 없는 판도 받는다. 받는 판을 이름으로 적어야 리뷰된다.
- 옛 버전으로 가입한 사람에게 새 판을 다시 동의받기 — 이번 개정은 궁합을 뺀 것(받는 정보가 줄었다)이고 테스트 기간이라 하지 않는다. 다시 동의받기는 약관 개정 계획에서 한다(결정 026 의 6번).

## 결과·재검토 조건
- 옛 목록이 비어 있지 않은 동안 옛 판을 본 가입도 받는다 — 길게 두지 않는다(4번).
- 정식 출시 뒤 약관을 바꿀 때도 같은 순서(서버가 둘 다 받기 → 앱 → 옛 목록 비우기)를 쓴다. 받는 정보가 늘어나는 개정이면 옛 판의 가입을 받아도 되는지 먼저 본다.
