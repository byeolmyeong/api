# 027. 푸시 수신 동의를 일시로 계정에 두고, 광고성 푸시는 푸시와 마케팅 동의가 둘 다 있을 때만 보낸다

> 상태: 활성 · 결정일 2026-11-19(소유자 "바로 시작해") · 결정 025(마케팅 수신 동의) 위에 더한다(대체하지 않는다) · 같은 계획의 026(약관 동의) · 028(프로필 그림)과 함께 · 계획 docs/plans/2026-11-19-signup-terms-push-consent.md · 계약은 docs/architecture.md "API 계약"

## 맥락
- 앱 온보딩의 약관 단계에 선택 항목 "푸시 알림 받기" 가 있다(필수 약관은 결정 026, 마케팅 정보 수신은 결정 025).
- 소유자(2026-11-19): 야간(21~08시)에는 광고를 보내지 않으므로 야간 광고 수신 동의는 받지 않는다.
- 푸시 발송 · 기기 토큰 · 운영체제 알림 권한은 아직 없다(푸시 기능 계획).

## 결정
1. **계정 칸**(V21, 더하기만, null 허용, 있던 행은 채우지 않는다): `push_consented_at`(null = 동의 안 함).
2. **가입**의 `pushConsent`(선택, 기본 false) — 켜면 그때의 서버 시각, 아니면 null. 새 계정에만 저장한다(결정 026 의 3번과 같은 규칙).
3. **`PATCH /account { pushConsent? }`** 로 바꾼다. 켜면 그때의 시각, 끄면 null, 같은 값이면 일시를 바꾸지 않는다. `GET /account` 에 `pushConsent` · `pushConsentAt`.
4. **광고성 푸시 규칙**(지금은 발송이 없다 — 발송 계획이 코드와 테스트로 지킨다): 광고성 푸시는 푸시 수신 동의(`push_consented_at`)와 마케팅 수신 동의(결정 025 의 `marketing_consented_at`)가 **둘 다** 있을 때만 보낸다. 한국 시간 21~08시에는 광고성 푸시를 보내지 않는다(그래서 야간 동의 칸이 없다). 푸시 동의만 있으면 서비스 알림만 보낸다.
5. **감사 기록**: `PATCH /account` 로 푸시 동의가 바뀔 때만 `PUSH_CONSENT_CHANGED`(detail `{ consent }` — 켬/끔만). 가입 때의 동의는 계정 칸에만 남는다. 이메일 · 닉네임은 넣지 않는다.
6. 탈퇴하면 이 칸은 계정 행과 함께 지워지고 감사 기록은 남는다(결정 015).

## 근거
- 동의를 일시 한 칸으로 두는 것은 결정 025 의 마케팅 동의와 같은 이유다(켬/끔과 시각을 한 칸이 답한다).
- 푸시 동의와 마케팅 동의를 따로 두면 서비스 알림만 받고 광고는 받지 않는 사람을 나눌 수 있다.

## 대안
- 야간 광고 수신 동의 칸 — 야간에 광고를 보내지 않으므로 받지 않는다(소유자).
- 동의를 참/거짓 칸 + 일시 칸 둘로 — 일시 하나로 둘 다 답한다.
- 푸시 동의 하나로 광고까지 — 광고성 정보는 마케팅 동의가 따로 있어야 한다(결정 025).

## 결과·재검토 조건
- 푸시 발송 계획이 4번 규칙을 지킨다.
- 처리방침의 수집 항목에 푸시 수신 동의 일시를 넣을지는 소유자가 정한다.
