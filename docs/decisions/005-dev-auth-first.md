# 005. 소셜 로그인 전에 개발용 로그인으로 기능부터 만든다

> 상태: 활성 · 결정일 2026-11-11 · 앱 쪽 기록: 앱 저장소 `docs/decisions/017-dev-session-and-boundaries.md`

## 맥락
제품 결정(앱 결정 009, 서버 003)은 스플래시 직후 구글·애플·카카오 가입 필수다. 그런데 소셜 로그인 클라이언트 등록에는 앱 이름·번들 ID 가 필요하고, 이름은 브랜딩 뒤에 정한다. 소유자는 로그인 없이 기능부터 만들고 브랜딩 뒤에 로그인을 붙이기로 했다.

## 결정
- `POST /auth/dev` 를 만든다: 요청 없이 개발용 계정(공급자 `DEV`)을 만들거나 찾아 세션 토큰을 준다. 설정 `byeolmyeong.auth.dev-enabled=true` 일 때만 열리고, 운영 설정에서는 404 다.
- 나머지 API 는 지금 계약대로 세션을 요구한다. 소유자는 지금처럼 세션 토큰에서만 얻는다.
- 구글·애플·카카오 토큰 검증과 만 14세 판정(`POST /auth/login`)은 브랜딩 뒤 태스크로 미룬다. 계정 테이블은 처음부터 공급자 칸을 둬서 나중에 마이그레이션이 필요 없게 한다.

## 근거
- 로그인을 완전히 빼면 해석·궁합·랭킹의 소유자 구조를 나중에 다시 만들어야 한다. 개발용 로그인은 소유자 구조를 그대로 두고 입구만 임시로 둔다.

## 대안
- 로그인 없이 기기 식별자로 저장 — 나중에 계정 병합이 필요하다.
- 소셜 로그인부터 — 클라이언트 등록이 브랜딩에 막힌다.

## 결과·재검토 조건
- 운영 배포 설정에 `dev-enabled` 가 켜져 있지 않은지 확인하는 테스트를 둔다(기본값 false).
- 소셜 로그인을 붙이면 `DEV` 계정은 운영 DB 에 없어야 한다.
