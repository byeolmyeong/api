# 서버 1.0.0

> 상태: 승인(태스크 1~5 먼저 실행) · 기준 2026-11-10 · 앱 쪽 계획: `../byeolmyeong-app/docs/plans/2026-11-10-app-1.0.0.md`

## 목표
- 무엇을: 차트를 계산하고, 그 차트로 글을 생성·저장하고, 로그인·궁합 초대·공유·알림을 맡는 서버.
- 누구를 위해: 앱 저장소의 앱(웹·iOS·Android, 이름 변경 예정).
- 끝나면: 앱 저장소 `../byeolmyeong-app/docs/release-1.0.0.md` 의 기능 F1~F9 가운데 서버가 맡는 부분이 모두 동작한다.

## 내 결정 (묻지 않고 고른 기본값)
- Kotlin, JVM 21, Gradle Kotlin DSL. 스키마는 Flyway, 테스트 DB 는 Testcontainers.
- 세션 토큰은 서버가 만든 무작위 값이고 DB 에는 해시만 둔다. JWT 는 쓰지 않는다. 이유: 서명·만료 관리 없이 로그아웃·삭제를 바로 반영한다.
- 리포트 생성은 같은 서버 안의 비동기 작업으로 한다. 별도 큐 서버를 두지 않는다. 틀리면 비용: 서버가 재시작되면 쓰던 리포트가 멈춘다 → 상태가 WRITING 인 채 10분이 지나면 다시 시작한다.
- 요청 수 제한은 서버 메모리에서 센다. 서버가 여러 대가 되면 다시 본다.
- 출생지 목록은 시·군·구 약 250개를 리소스 파일로 둔다.

## 범위 밖
- 결제·구매 확인, 광고 판정(1.1.0), 투두·조각·레벨업(1.1.0), 그룹 궁합(1.1.0), 영어·해외 출생지(1.2.0), 오늘의 운세, 키론, 운영 배포.

## 전역 제약
- 소유자는 세션에서만 얻는다. 남의 자원은 404.
- `chart` 패키지는 DB·HTTP·AI 를 import 하지 않는다.
- API 키는 환경 변수에만. 출생 정보·차트·토큰을 로그에 남기지 않는다.
- API 계약을 바꾸면 docs/architecture.md 의 표를 같은 커밋에서 고친다.
- 새 동작은 실패하는 테스트를 먼저 본다.
