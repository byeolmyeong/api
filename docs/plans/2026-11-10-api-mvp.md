# 서버 MVP: 익명 계정 + 해석 생성 + 공유 조회

> 상태: 제안 · 기준 2026-11-10 · 앱 저장소 계획(`../byeolmyeong-app/docs/plans/2026-11-10-mvp.md`)의 태스크 6·7·10 에서 서버 부분을 옮겨 온 것이다.

## 목표
- 무엇을: 앱이 보낸 차트로 AI 해석을 만들어 저장하고, 공유 링크로 요약 해석을 내보내는 서버.
- 누구를 위해: 별명 앱.
- 끝나면: 앱이 `POST /readings` 로 해석을 받고 `GET /shared/{shareId}` 로 공유 페이지를 그린다.

## 결정된 전제
- 구조·API 계약·해석 생성 규칙: docs/architecture.md
- 스택·저장소 분리: docs/decisions/001-spring-boot-postgres.md
- 제품 컨셉(해석 말투): 앱 저장소 `../byeolmyeong-app/docs/product.md`
- 규칙: docs/golden-rules.md

## 내 결정 (묻지 않고 고른 기본값)
- Java 21(로컬에 설치된 LTS), Gradle.
- 스키마 변경은 마이그레이션 도구(Flyway)로 관리한다.
- 테스트의 DB 는 Testcontainers 로 띄운다(로컬에 Docker 가 있다).
- 토큰은 서버가 만든 무작위 값이고 DB 에는 해시만 저장한다. JWT 는 쓰지 않는다. 이유: 익명 계정 하나에 토큰 하나라 서명·만료 관리가 필요 없다.

## 범위 밖
- 결제·구매 확인, 소셜 로그인, 계정 삭제 API, 운영 배포.

## 전역 제약
- 소유자는 토큰에서만 얻는다. 남의 자원은 404.
- API 키는 환경 변수에만. 출생 정보·차트 본문을 로그에 남기지 않는다.
- API 계약을 바꾸면 docs/architecture.md 의 표를 같은 커밋에서 고친다.

## 태스크

### 1. api-skeleton · 상태: 대기
- 읽을 것: docs/decisions/001-spring-boot-postgres.md, docs/architecture.md, `.claude/rules/web-backend.md`·`multi-tenant.md`
- 할 것: Spring Boot 프로젝트(Gradle, Java 21, 현재 안정 버전 — 정한 버전을 ADR 001 에 적고 [확인 필요]를 지운다). PostgreSQL + Flyway 로 테이블 `accounts`·`readings`(docs/architecture.md "데이터"). 로컬 DB 는 `compose.yaml`. `POST /accounts` 로 익명 계정과 토큰 발급, 토큰 인증 필터. `.claude/skills/verify/SKILL.md` 표와 `.env.example` 을 채운다.
- 주는 것: `./gradlew build`, 인증된 요청에서 소유자 id 를 얻는 방법(인자 리졸버 또는 동등한 한 곳).
- 하지 말 것: `purchases` 테이블. 이유: 결제는 보류다. 토큰 원문 저장. 이유: DB 가 새면 모든 계정이 뚫린다.
- 검증: `./gradlew build` 통과 — 토큰 없이 `POST /readings` 401, 잘못된 토큰 401, `POST /accounts` 가 매번 다른 토큰.
- 실행 패턴: 혼자

### 2. reading-generation · 상태: 대기
- 읽을 것: docs/architecture.md "API 계약"·"해석 생성 규칙", 태스크 1 의 인증·테이블, `.claude/rules/external-api.md`, 앱 저장소 `../byeolmyeong-app/docs/product.md` "컨셉"
- 할 것: `POST /readings`. 차트 JSON 검증(천체 10개, 황경 범위, `timeKnown`), (소유자, 차트 해시, 종류) 저장본이 있으면 반환, 없으면 생성 인터페이스 `ReadingGenerator` 를 통해 OpenAI API 로 생성해 저장. 프롬프트는 `src/main/resources/prompts/` 파일. 모델과 호출 방식은 공식 문서를 확인해 정하고 실행 기록에 `결정:` 으로 남긴다. 응답이 정해진 구조(sections)가 아니면 저장하지 않고 502.
- 주는 것: `ReadingGenerator` 인터페이스, 응답 `{ sections, shareId }`, 환경 변수 이름 `OPENAI_API_KEY`.
- 하지 말 것: 실패·빈 응답 저장. 이유: 실패가 캐시되면 그 차트는 영영 해석이 없다. 차트 본문 로깅. 이유: 출생 정보를 역산할 수 있다.
- 검증: `./gradlew test` — 같은 차트 두 번 요청 시 생성 1회(가짜 `ReadingGenerator`), 동시 요청 2건에 저장 1행, 황경 400 인 차트 400, 생성 오류 시 저장 0건, 다른 계정은 같은 차트라도 따로 생성. 실제 생성 결과 5건을 사람이 읽어 용어·단정 표현 0건인지 확인(실행 기록에 발췌).
- 실행 패턴: 혼자
- 차단 예상: OpenAI API 키 발급은 사용자가 한다.

## 검증
- `/verify` 표 전체 통과.
- 로컬에서 앱을 띄워 차트 입력 → 요약 해석 → 공유 링크 열기까지.

## 리뷰 초점
1. 생성 도중 실패: OpenAI 응답이 중간에 끊기면 반쪽 해석이 저장되지 않는가 (태스크 2).
2. 동시 요청: 두 번째 요청이 unique 위반으로 500 을 내지 않고 저장본을 돌려주는가 (태스크 2).
3. 시각 모름 차트: `houses` 가 null 일 때 검증이 400 을 내지 않는가 (태스크 2).
4. 공유 식별자 길이: 추측·순회로 남의 해석을 열 수 없는가 (태스크 3).
5. 토큰 분실: 앱 데이터를 지우면 이전 해석에 접근할 수 없다. 지금은 복구 수단이 없다. [확인 필요]
